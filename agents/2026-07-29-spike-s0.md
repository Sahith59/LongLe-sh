# Spike S0 — Agent SDK under subscription OAuth (2026-07-29)

**Verdict: PASS.** Phase A is unblocked. Three findings below are binding on Phase A's design and tests.

## What was tested

`@anthropic-ai/claude-agent-sdk` (fresh npm install, Node v26) driven headlessly on Sahith's machine, authenticated only by the Claude Code CLI's existing subscription OAuth — no API key anywhere.

## Results

| Check | Result |
|---|---|
| Query runs under subscription OAuth (`apiKeySource: "none"`) | ✅ |
| Streaming messages arrive (init → assistant → result) | ✅ |
| Session persisted with reusable session ID | ✅ |
| `canUseTool` fires for a gated tool (Write) | ✅ |
| Approval via callback → tool actually executes → real file on disk | ✅ (traced end-to-end) |
| Cost visible per run | ✅ (~$0.10–0.24/run) |

## Findings that bind Phase A

1. **Auto-approved tools silently bypass `canUseTool`.** A plain `echo` ran with the callback never firing. Consequence: the phone's Activity feed cannot rely on `canUseTool` for visibility — it needs the `PreToolUse` hook to observe auto-approved actions, exactly as the research predicted.
2. **cwd handling is not trustworthy by default.** With `options.cwd` set to the spike directory, the agent wrote its file to `$HOME` instead. Phase A must pin and *verify* per-session cwd (dedicated test), since session resume is also keyed to cwd.
3. **Never assert on the agent's word.** The agent replied "DONE" in a run where the observable state told a more complicated story (write → error → read → done). Test rule for the whole project: assertions target observable side effects — files, DB rows, tool_result payloads — never the agent's final text or the mere firing of a callback.
